# AGENTS.md

Rules for anyone, human or agent, working in this repository. What the project is and how to build, wire and flash it: [`README.md`](README.md).

## Rules

1. **ATtiny85 only.** PIC and the ATtiny84 are research sources, never build targets. Every board from the PU-7 to the PM-41(2) is a target.
2. **C17, MISRA C:2012 at zero deviations, pinned toolchain.** Every build, check and test runs in the pinned Docker image through `make`; only `avrdude` runs on the host.
3. **Registers only in assembly.** Hardware access lives in `src/port.S` (the console's signals) and `src/port_chip.S` (the chip's housekeeping) behind C prototypes; no C file includes an `avr/` or `util/` header.
4. **Layers.** The logic layer (`region`, `subq`, `board_mode`, `inject`, `indicator`, `calib`, `trim`, `supply`, `loop`, and `trace`, linked only into the trace image) includes only the standard headers and `pscu/` and is host-tested; platform C (`engine`, `run`, `main`) may add `port/`; only the two `.S` files touch hardware.
5. **One mode, fully stealth.** SCEx is injected only inside the SUBQ region-check window, at most `PSCU_STEALTH_STRINGS` strings per arming, `PSCU_STEALTH_GAP_FRAMES` frames apart, using the canonical 4 ms-bit mirror model; outside the window DATA is high-Z. No string starts once the console reads the program area; a string already under way finishes, within 181 ms. Only a new lead-in read reopens the window, under the same cap and gap: a TOC re-read, as in the anti-mod v2 check, or a new disc, seen as `PSCU_DISC_GONE_MS` without a valid SUBQ frame. No mode system, no reset or lid wiring.
6. **One region per build.** `REGION=jp|us|eu`; the chip emits only that region's string, never all three.
7. **No hardware on the console beyond the chip.** Only the ATtiny85, four bare signal wires (SQCK, SUBQ, DATA, WFCK) and power; PB5 stays RESET so the chip remains ISP-programmable. The exception is the one optional board in `hardware/`: through-hole parts only, a DIP-8 socket, a 100 nF decoupling capacitor, a 220 µF bulk capacitor and a 10 kΩ RESET pull-up always fitted, one hole-free top-side pad per signal plus supply and ground, and three optional headers: a keyed ISP header, a keyed 3-pin indicator header (GND, VCC, PB3) for a cable to whatever indicator the builder chooses, such as an LED with its resistor, an active buzzer or a board of their own, and a six-pin serial header for the trace profile. The board carries no LED, buzzer, switch or other indicator part. No part sits in series with a console line or loads it, and the firmware behaves identically on the board and on the bare chip. The optional PB3 indicator, whatever the builder hangs on it, never gates, delays or times a feature, and gives up its pin to any feature that needs it. It is the only diagnostic channel; the build-time `PROFILE`, `debug`, `final` or `trace`, changes only that pin, and `trace` makes it a serial line that sends a boot report, each captured SUBQ frame and at most one line per decision in the gap after the frame, never inside a string. EEPROM holds only values measured on this console, never a mode or a user setting, and a missing or damaged record falls back to the fixed defaults.
8. **Internal oscillator, trimmed.** The chip runs from its internal 8 MHz RC oscillator, never from an external clock or crystal. It trims OSCCAL against the console's SUBQ frame rate, up to `PSCU_TRIM_MAX_STEP` notches per batch and one notch per write, within `PSCU_TRIM_MAX_OFFSET` of the factory value and never across CAL7. Every cycle-based constant is derived from F_CPU.
9. **No boot-ROM patch.** The chip does SCEx only; consoles with a second region check in the boot ROM need a patched BIOS.
10. **Every timing constant states its origin:** a source and location, a datasheet figure, a measurement, or, for a value no source fixes, a design bound with the reason for its size. None is copied from another chip without derivation. When sources disagree, a long-deployed release wins over a newer one unless a reason is stated.
11. **No proprietary ROM content** in the tree; BIOS identities and behaviour only.
12. **Didactic comments** in every source file, tests and tools included, a deliberate override of the global no-comments rule: explain the hardware context, the reason for a constant or a design choice, and the invariant a block upholds, only where the code cannot say it; never restate the code or record how a fact was found. Keep the two SPDX header lines.
13. **Gates before every push:** `make all size analyse test repro mutate` green, 100 percent host line and branch coverage, every mutant killed, zero warnings. A bug fix adds a test that fails without it.
14. **Conventional commit subjects** of at most 50 characters; `make hooks` enforces them, and releases are versioned from them.
15. **Every README claim links to its source.** In `README.md`, `README.ja.md` and `README.zh.md`, every table row, list item and paragraph outside code links to its source: a permalink pinned to a commit, a stable document such as a datasheet, or, for this firmware's behaviour, the source file that implements it. A host test enforces it.
16. **The board is symmetric and quiet.** The layout is symmetric about the board's vertical centre line: the chip, the serial header and the row of wire pads sit on it, and the parts on either side balance each other. Every track is as wide as its route allows, widest first from 1.0 mm down to the 0.4 mm floor, keeps 1.0 mm from other tracks and 0.8 mm from pads, changes direction only in steps of 45 degrees drawn as tangent arcs, never a sharp corner, and runs on top over an unbroken bottom ground plane, so it neither radiates nor picks up interference. The board generator asserts the symmetry and the router enforces the rest; DRC and ERC are clean before any board file is committed.
